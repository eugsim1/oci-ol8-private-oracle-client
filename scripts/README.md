# Script runbook

The scripts separate infrastructure deployment, operating-system provisioning,
resource lifecycle operations, and interactive access. Run them from an
external Linux controller with the repository checkout and Terraform state.

## Quick choice

| Need | Script | Starts Compute/ADB | Creates session | Runs Ansible | Opens SSH |
|---|---|---:|---:|---:|---:|
| First deployment | `deploy.sh` | Terraform-managed | Yes | Yes | No |
| Start stopped services and log in | `start-and-connect.sh` | Yes, if stopped | Fresh session | No | Yes |
| Wait only for Bastion plugin readiness | `wait-for-bastion-plugin.sh` | No | No | No | No |
| Stop ADB and Compute | `stop-all.sh` | Stops both | Deletes open sessions | No | No |
| Renew only the Terraform session | `renew-bastion-session.sh` | No | Replaces session | No | No |
| Full lifecycle control or automation | `manage-existing-stack.sh` | Optional | Optional | No | Optional |
| Connect through the current active session | `connect-oracle-server.sh` | No | No | No | Yes |
| Configure or reconfigure Linux | `run-ansible.sh` | No | No | Yes | No |
| Open the private VNC tunnel | `open-vnc-tunnel.sh` | No | No | No | SSH tunnel |
| Generate Streamlit assets on Windows | `generate-output-assets.ps1` | No | No | No | No |
| Generate Streamlit assets on Linux | `generate-output-assets.sh` | No | No | No | No |
| Open Streamlit from Windows using Terraform and OCI config | `connect-streamlit-from-terraform.ps1` | No | Creates connector session | No | SSH tunnel |
| Select the compartment-safe state | `select-compartment-workspace.sh` | No | No | No | No |

## Created artifacts used by the scripts

The access scripts reuse, rather than recreate, these deployment artifacts:

- Terraform outputs: Compute OCID, ADB OCID, Bastion OCID, private IP, region,
  session state/OCID, and Bastion public-key path.
- `terraform/terraform.tfvars`: selects the compartment-derived Terraform
  workspace before state outputs are read.
- The private key adjacent to the Terraform public key (`key.pub` -> `key`).
- The public key adjacent to whichever private key is selected. This prevents a
  cached or inventory private key from being paired with an older Terraform
  public-key path.
- `reports/ssh-connection.env`: controller-only connection cache generated by
  `run-ansible.sh`, mode `0600`.
- `ansible/inventory/hosts.yml`: final private-key fallback.
- `reports/stack-lifecycle-*.csv`: timestamped lifecycle audit generated by
  `manage-existing-stack.sh` and therefore also by `start-and-connect.sh`.

No script reads a private key from Terraform state. Terraform stores only the
configured local public-key path and sends only public-key content to OCI.

## 1. Deploy the complete environment

```bash
export TF_VAR_adb_admin_password='<secure value>'
./scripts/deploy.sh terraform.tfvars /secure/keys/bastion_key
```

`deploy.sh` selects the compartment workspace, applies Terraform, calls
`run-ansible.sh`, and creates a timestamped deployment report. It is for initial
deployment or an approved infrastructure change, not routine login.

## 2. Start stopped resources and connect

This is the normal operator entry point when Compute or Autonomous Database may
be stopped:

```bash
./scripts/start-and-connect.sh --tfvars terraform.tfvars
```

The wrapper is deliberately split into three independently visible stages:

1. Selects the Terraform workspace derived from `compartment_id`.
2. Resolves the existing key pair from deployment artifacts.
3. Reads existing resource OCIDs, private IP, and region from Terraform.
4. Stage 1 starts Compute/ADB only when `STOPPED`, then waits for Compute
   `RUNNING` and ADB `AVAILABLE`.
5. Stage 2 invokes `wait-for-bastion-plugin.sh`, which prints numbered checks
   until the Compute `Bastion` plugin reaches `RUNNING`.
6. Missing plugin inventory, transient OCI CLI/API failures, and `INVALID`
   (status not yet recognizable by OCI) are retried until the plugin timeout.
   `NOT_SUPPORTED` remains an immediate terminal error.
7. Stage 3 creates a fresh managed SSH session and waits for `ACTIVE`.
8. Opens interactive SSH to `oracle@<private-ip>` through OCI Bastion.
9. Writes separate resource-start and session-creation audit CSVs to
   `reports/stack-lifecycle-*.csv`.

No Ansible playbook runs. Preview all OCI mutations first:

```bash
./scripts/start-and-connect.sh \
  --tfvars terraform.tfvars \
  --dry-run
```

Use an explicit key or OCI authentication mode when required:

```bash
./scripts/start-and-connect.sh \
  --tfvars terraform.tfvars \
  --ssh-private-key /secure/keys/bastion_key \
  --ssh-public-key /secure/keys/bastion_key.pub \
  --profile DEFAULT \
  --session-ttl 10800 \
  --wait-seconds 3600 \
  --bastion-plugin-wait-seconds 900 \
  --poll-seconds 10
```

`--ssh-public-key` is optional when `/secure/keys/bastion_key.pub` exists. If
the selected private key has no adjacent `.pub` file, supply the matching
public key explicitly (or set `SSH_PUBLIC_KEY_PATH`). The wrapper never mixes a
cached/inventory private key with an unrelated Terraform public-key artifact.

```bash
./scripts/start-and-connect.sh \
  --tfvars terraform.tfvars \
  --auth instance_principal \
  --profile DEFAULT
```

Run `./scripts/start-and-connect.sh --help` for all artifact, workspace, OCI,
SSH, timeout, dry-run, and report flags.

Run the readiness gate separately for diagnosis or automation:

```bash
./scripts/wait-for-bastion-plugin.sh \
  --terraform-dir ./terraform \
  --profile DEFAULT \
  --wait-seconds 900 \
  --poll-seconds 10
```

It resolves `instance_id` and `region` from Terraform when omitted. Use
`--instance-id` and `--region` when running without the Terraform state.

## 3. Stop Autonomous Database and Compute

Run this from the external controller, not from the Compute instance being
stopped. Preview the selected resources and operations first:

```bash
./scripts/stop-all.sh --tfvars terraform.tfvars --dry-run
```

Then close every non-deleted session for the selected Bastion, stop Autonomous
Database, gracefully stop Compute with `SOFTSTOP`, and wait for both resources
to reach `STOPPED`:

```bash
./scripts/stop-all.sh --tfvars terraform.tfvars
```

Use `--force-stop` only for an approved emergency hard power-off. Every run
writes a timestamped lifecycle CSV under `reports/`.

## 4. Renew only the Terraform-managed Bastion session

Use renewal when Compute is already `RUNNING`, ADB is already `AVAILABLE`, and
only the session recorded in Terraform has expired:

```bash
./scripts/renew-bastion-session.sh terraform.tfvars
```

It selects the correct workspace, uses targeted `-replace` on only
`module.bastion.oci_bastion_session.ansible[0]`, performs a refresh-only apply,
and waits for the new session to become `ACTIVE`.

The word `ansible` in that address is only the existing Terraform resource
label. Terraform replaces an OCI Bastion Session; no Ansible executable or
playbook is invoked.

It intentionally does **not**:

- run `run-ansible.sh` or any playbook;
- start Compute or Autonomous Database;
- rerun the full Terraform deployment;
- open an interactive SSH process.

After renewal, connect with:

```bash
./scripts/connect-oracle-server.sh
```

If the resources may be stopped, use `start-and-connect.sh` instead. Relevant
environment flags are:

| Variable | Default | Purpose |
|---|---|---|
| `BASTION_SESSION_ACTIVE_TIMEOUT` | `300` | Seconds to wait for `ACTIVE` |
| `TERRAFORM_BIN` | `terraform` | Terraform executable/path |
| `WORKSPACE_SELECTOR_BIN` | Project selector | Test/advanced selector override |

## 5. Full lifecycle operations

`manage-existing-stack.sh` is the underlying lifecycle engine. It supports
explicit test/imported OCIDs as well as Terraform outputs.

```bash
./scripts/manage-existing-stack.sh --dry-run
./scripts/manage-existing-stack.sh --start
./scripts/manage-existing-stack.sh --start --connect
./scripts/manage-existing-stack.sh --start-resources-only
./scripts/manage-existing-stack.sh --create-session-only
./scripts/manage-existing-stack.sh --stop-all --dry-run
./scripts/manage-existing-stack.sh --stop-all
```

`--stop-all` closes every non-deleted session belonging to the selected
Bastion, stops ADB, and requests graceful Compute `SOFTSTOP`. Do not run it from
the Compute instance being stopped. See
[`../docs/EXISTING_STACK_LIFECYCLE.md`](../docs/EXISTING_STACK_LIFECYCLE.md) for
all flags, IAM policies, test OCIDs, CSV fields, failure handling, and rollback.

## 6. Connect through the current session

```bash
./scripts/connect-oracle-server.sh
```

This script prefers current Terraform outputs and falls back to
`reports/ssh-connection.env` and the generated inventory. It refuses to connect
unless the selected session is `ACTIVE`. It does not start resources or create
a session.

## 7. Run Ansible separately

```bash
./scripts/run-ansible.sh /secure/keys/bastion_key
```

Run this only when Linux packages, wallet configuration, application checkout,
database validation, GUI configuration, or the optional FOCUS loader must be
provisioned again. Session renewal and routine login do not require Ansible.
See [`../ansible/README.md`](../ansible/README.md) for its password and feature
flags.

## 8. Open the VNC tunnel

```bash
VNC_LOCAL_PORT=5901 \
./scripts/open-vnc-tunnel.sh /secure/keys/bastion_key
```

The current Terraform-managed session must be `ACTIVE`. The script binds only
the local controller port and forwards to `127.0.0.1:5901` on the private host.

## 9. Select the Terraform workspace

```bash
./scripts/select-compartment-workspace.sh terraform.tfvars
```

The script hashes the configured compartment OCID into a deterministic
workspace name. It refuses an unsafe workspace switch when the current
workspace already contains resources unless the documented explicit override
is supplied.

## 10. Open Streamlit from Windows using the asset inventory

The launcher normally reads `scripts\output_assets.txt`; therefore the
connection command no longer needs OCIDs, profile values, or key paths:

```powershell
.\scripts\connect-streamlit-from-terraform.ps1
```

Verify the complete flow without creating a Bastion session:

```powershell
.\scripts\connect-streamlit-from-terraform.ps1 -DryRun
```

The real `output_assets.txt` is local infrastructure metadata and is ignored
by Git. The repository contains `output_assets.txt.example` only. The
inventory contains paths and identifiers, never passwords or private-key
contents.

### How `output_assets.txt` is consumed

Do **not** pass `output_assets.txt` directly to
`connect-streamlit-api-key-auth.ps1`. That lower-level connector accepts
individual parameters and has no asset-file parameter. Always give the file to
the project wrapper, which validates the inventory and converts its entries
into connector parameters:

```text
output_assets.txt
        -> connect-streamlit-from-terraform.ps1
        -> connect-streamlit-api-key-auth.ps1
        -> OCI Bastion session and SSH port-forward
```

Use an explicit inventory path on Windows:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File ".\scripts\connect-streamlit-from-terraform.ps1" `
  -AssetsFilePath ".\scripts\output_assets.txt"
```

Use the same wrapper on Linux when PowerShell 7 (`pwsh`) and the referenced
PowerShell connector are installed:

```bash
pwsh -NoProfile \
  -File ./scripts/connect-streamlit-from-terraform.ps1 \
  -AssetsFilePath ./scripts/output_assets.txt
```

The inventory entry below must name the actual lower-level connector file; it
must not point back to `output_assets.txt`:

```text
ConnectorScriptPath=/path/to/connect-streamlit-api-key-auth.ps1
```

Before execution, the wrapper requires every referenced file to exist. In
particular, verify these path entries:

- `SshPrivateKeyPath`
- `SshPublicKeyPath`, when present
- `ApiPrivateKeyPath`
- `OciConfigFilePath`
- `ConnectorScriptPath`

To regenerate the inventory from the currently selected Terraform state and
the `STREAMLIT_API_KEY` profile in `$HOME\.oci\config`, run:

```powershell
.\scripts\generate-output-assets.ps1 `
  -ProfileName 'STREAMLIT_API_KEY' `
  -SshPrivateKeyPath "$HOME\.ssh\bastion_ed25519" `
  -SshPublicKeyPath "$HOME\.ssh\bastion_ed25519.pub" `
  -ConnectorScriptPath 'C:\path\to\focus-loader-report-upload-source\windows-api-key-auth-streamlit\connect-streamlit-api-key-auth.ps1'
```

The generator only writes the inventory; it never creates a Bastion session
or starts SSH. `-SshPublicKeyPath` is optional when the connector can use the
public key adjacent to the private key. Use `-AssetsFilePath` for a different
inventory, `-TerraformDirectory` for a different checkout, and
`-OciConfigFilePath` for a non-default OCI configuration.

Before refreshing, verify that Terraform is using the deployed workspace:

```powershell
terraform -chdir=.\terraform workspace show
terraform -chdir=.\terraform output bastion_id
```

### Linux / Oracle Linux 8 generator

Run the native Bash generator from the Linux controller that holds the active
Terraform state and OCI configuration:

```bash
chmod 0700 scripts/generate-output-assets.sh
./scripts/generate-output-assets.sh \
  --profile STREAMLIT_API_KEY \
  --ssh-private-key "$HOME/.ssh/bastion_ed25519" \
  --ssh-public-key "$HOME/.ssh/bastion_ed25519.pub" \
  --connector-script "/path/to/connect-streamlit-api-key-auth.ps1"
```

It reads `bastion_id`, `instance_id`, `private_ip`, and `region` from the
currently selected Terraform workspace. It reads `user`, `tenancy`,
`fingerprint`, and `key_file` from `$HOME/.oci/config`, requires no `jq`, and
writes `scripts/output_assets.txt` atomically with permissions `0600`.

Paths stored in the inventory are paths on the machine running the generator.
If the file is copied from Linux to a Windows laptop, replace the SSH key, API
key, OCI config, and connector paths with their Windows equivalents before
running the PowerShell wrapper. The OCI identifiers, region, IP address,
profile name, ports, and timeout values remain portable.

## Testing

Offline tests use test OCIDs and mock executables; they do not contact OCI:

```bash
./tests/test-manage-existing-stack.sh
./tests/test-wait-for-bastion-plugin.sh
./tests/test-bastion-session-scripts.sh
```

```bash
shellcheck scripts/*.sh tests/*.sh
```

## Troubleshooting

| Symptom | Resolution |
|---|---|
| Terraform output is empty | Confirm the selected tfvars/workspace and state backend. |
| `output_assets.txt` is rejected by `connect-streamlit-api-key-auth.ps1` | Pass the file to `connect-streamlit-from-terraform.ps1 -AssetsFilePath`, not directly to the lower-level connector. |
| A path from a copied Linux inventory is missing on Windows | Replace the SSH key, API key, OCI config, and connector paths with their Windows equivalents. |
| Private key cannot be resolved | Pass `--ssh-private-key`; confirm the matching `.pub` file exists. |
| Compute remains `STOPPED` | Check OCI CLI identity, instance state, and `manage instance-family` permission. |
| Bastion plugin reports `INVALID` | The waiter now keeps polling because OCI defines this as an unrecognized status; allow it to reach `RUNNING` or the timeout. |
| Bastion plugin never reaches `RUNNING` | Run `wait-for-bastion-plugin.sh` directly to see every state/query error; check Oracle Cloud Agent and increase `--bastion-plugin-wait-seconds` if startup legitimately needs longer. `NOT_SUPPORTED` requires a compatible image/agent rather than more waiting. |
| ADB remains `STOPPED` | Check database state and `manage autonomous-database-family` permission. |
| Session creation fails | Confirm Bastion target subnet, agent/plugin status, public key, NSGs, and session IAM. |
| SSH times out after `ACTIVE` | Check private IP, port 22 NSG rules, `sshd`, target username, and matching key. |
| Renewal fails while resources are stopped | Use `start-and-connect.sh`, which starts them before creating a session. |

Do not commit generated reports, inventories, tfvars, state, wallets, or keys.
The repository `.gitignore` excludes these artifacts, but operators remain
responsible for protecting controller files and shell history.
